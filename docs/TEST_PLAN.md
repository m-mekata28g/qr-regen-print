# テスト計画

動作確認のための、テスト項目と受け入れ基準です。更新したあとの確認にも使います。

- 仕様：[SPECIFICATION.md](SPECIFICATION.md)（業務ルール BR-xx）
- 導入手順：[DEPLOYMENT.md](DEPLOYMENT.md)

## 1. 方針

- すべての画面を、実際の端末とブラウザで確認する。
- 公開しているアプリで試す場合は、**テスト用のデータとテスト用の送信先**を使う。実際の業務データは使わない。
- 結果は「結果」の欄に、○（合格）、×（不合格）、－（対象外）で記入する。不合格のときは、備考に内容を書く。

## 2. テスト環境

| 区分 | 内容 |
|---|---|
| スマホ（Android） | Chrome |
| スマホ（iPhone） | Safari |
| PC | Chrome または Edge |
| 通信 | Wi-Fi、モバイル回線の両方で、導入時に1回ずつ確認する |
| 公開URL | GitHub PagesのURL（HTTPS） |
| GAS | テスト用のトークンと、テスト用の送信先で作成したもの |

### テストデータ

実際のURLの代わりに、次のようなテスト用のURLを入れたQRコードを使います。

| 用途 | 内容の例 |
|---|---|
| 正常なURL | `https://example.com/test/001`、`https://example.com/test/002` … |
| URL以外 | `HELLO`（文字だけのQRコード） |
| 長いURL | `https://example.com/test/` に、100文字ほどの文字列を足したもの |
| 本店名・ホール名 | `本店A,ホールA1`、`本店A,ホールA2`、`本店B,ホールB1` |

> テスト用のQRコードは、無料のQRコード作成サービスや、このアプリのPC側で作って、画面や紙に表示します。

## 6. 受け入れ基準

次の条件をすべて満たしたときに、受け入れ可とします。

1. 「導入時の確認」（IN-01〜IN-08）が、すべて合格している。
2. 「機能テスト」（SC、SN、GN、PR、PD、ST）の項目が、すべて合格している。不合格の項目がある場合は、影響を判断し、対応方針（修正または運用での回避）を記録している。
3. 「共通・非機能のテスト」（CM-01〜CM-12）が、すべて合格している。
4. Android（Chrome）、iPhone（Safari）、PC（Chrome または Edge）の、それぞれで、IN-07 とSC-01、PR-07 が合格している。
5. 公開するリポジトリに、秘密情報が含まれていない（CM-09）。
