# 導入・更新手順

GitHub PagesとGoogle Apps Script（GAS）の構築手順、アプリの初期設定、更新の方法をまとめた文書です。

- 日常の運用：[OPERATIONS.md](OPERATIONS.md)
- 動作確認の項目：[TEST_PLAN.md](TEST_PLAN.md)

## 1. 全体の手順

| 順番 | 作業 | 場所 |
|---|---|---|
| 1 | 公開前の確認（秘密情報が入っていないこと） | ローカル |
| 2 | GitHubにリポジトリを作成し、ファイルを置く | GitHub |
| 3 | GitHub Pagesを有効にする | GitHub |
| 4 | GASを作成してデプロイする | Google Apps Script |
| 5 | アプリに設定を入力し、接続テストをする | スマホ・PC |
| 6 | 動作を確認する | スマホ・PC |

## 2. 公開前の確認

GitHub Pagesの無料プランで使うには、リポジトリを**公開（Public）**にします。誰でも中身を見られるので、次のものが含まれていないことを確認してください。

| 確認すること | 内容 |
|---|---|
| 転送トークン | `Code.gs` の `TRANSFER_TOKEN` は、ダミー（例：`'*****'`）のままにする |
| メールアドレス | `Code.gs` の `DEFAULT_TO` は、ダミー（例：`example@gmail.com`）のままにする |
| GASのURL | READMEや文書に、実際のウェブアプリURLを書かない |
| 取引先・店舗の名前 | サンプルや説明に、実在の名前を書かない |

> 実際のトークンとメールアドレスは、Google側のApps Scriptと、各端末のアプリの設定にだけ入れます。リポジトリには入れません。

## 3. GitHub Pagesの公開

1. GitHubで、新しいリポジトリを作成します（Publicを選びます）。
2. このリポジトリのファイルを、すべてアップロードします。`index.html` を、リポジトリの一番上の階層に置きます。
3. リポジトリの **Settings → Pages** を開きます。
4. **Branch** を `main`、フォルダを `/ (root)` にして、**Save** を押します。
5. 1〜3分後に、公開URLが表示されます。

```
https://<ユーザー名>.github.io/<リポジトリ名>/
```

このURLが、アプリのURLです。スマホのカメラはHTTPSのページでしか使えませんが、GitHub PagesはHTTPSで配信されます。

## 4. Google Apps Script（GAS）の構築

### 4.1 プロジェクトの作成と設定

1. [Google Apps Script](https://script.google.com/) を開き、**新しいプロジェクト**を作成します。
2. このリポジトリの `Code.gs` の内容を、エディタに貼り付けます。
3. 次の値を、自分の値に書き換えて、保存します。

| 設定 | 内容 | 注意 |
|---|---|---|
| `TRANSFER_TOKEN` | 合言葉となる文字列 | 推測されにくい、長い文字列にする。他人に教えない |
| `DEFAULT_TO` | メールを受け取るGmailアドレス | 承認テストのメールもここに届く |
| `SUBJECT_PREFIX` | メールの件名の先頭に付ける文字 | 任意 |

### 4.2 権限の承認

1. エディタの関数の選択欄で `authorizeOnce` を選びます。
2. **実行** を押し、画面の案内に従って、メール送信の権限を承認します。
3. `DEFAULT_TO` に、承認テストのメールが届けば完了です。

### 4.3 ウェブアプリとしてデプロイ

1. **デプロイ → 新しいデプロイ** を選びます。
2. 種類で **ウェブアプリ** を選びます。
3. 次のように設定します。

| 設定 | 値 |
|---|---|
| 次のユーザーとして実行 | **自分** |
| アクセスできるユーザー | **全員** |

4. **デプロイ** を押します。
5. 表示された**ウェブアプリのURL**（`…/exec` で終わる）を、安全な場所に控えます。

### 4.4 コードを更新したとき

1. エディタでコードを直して、保存します。
2. **デプロイ → デプロイを管理** を開き、鉛筆のアイコンで編集します。
3. バージョンを **新しいバージョン** にして、**デプロイ** を押します。

> 保存しただけでは、動いているのは古いコードのままです。必ず、新しいバージョンとしてデプロイしてください。ウェブアプリのURLは変わりません。

## 5. アプリの初期設定

スマホとPCの**両方**で、アプリの「⚙ 設定」を開いて、入力します。

### 5.1 GAS・送信先

| 項目 | 入力する値 |
|---|---|
| Google Apps Script URL | 手順4.3で控えたウェブアプリのURL |
| 転送トークン | `Code.gs` の `TRANSFER_TOKEN` と同じ文字列 |
| 送信先Gmail | `DEFAULT_TO` と同じ（または受け取りたい）アドレス |

入力したら「移行設定を保存」を押し、続けて「GAS接続テスト」を押します。「接続OK：logistics-system v6.0 …」と表示されれば、接続できています。

### 5.2 本店名 / ホール名

「本店名 / ホール名設定」に、1行に1組ずつ入力して、「本店名 / ホールリストを保存」を押します。

```
本店A,ホールA1
本店A,ホールA2
本店B,ホールB1
```

### 5.3 スマホのホーム画面に追加

ブラウザのメニューから「ホーム画面に追加」を選ぶと、アプリのように起動できます。

## 6. 動作確認

導入が終わったら、[TEST_PLAN.md](TEST_PLAN.md) の「導入時の確認」の項目を実施してください。最低限、次の3つを確認します。

1. スマホでQRコードを読み取り、URLが保存される
2. 「URL送信」でメールが届き、TXTが添付されている
3. PCでTXTを読み込むと、QRコードが生成される

## 7. アプリの更新

1. 更新したファイルを、リポジトリに上書きします（GitHubの **Add file → Upload files**、または対象ファイルの **Edit**）。
2. **Commit changes** を押します。
3. 1〜3分後に、公開URLへ反映されます。
4. `Code.gs` を変えたときだけ、Apps Script側も貼り替えて、新しいバージョンとしてデプロイします。
5. 利用者には、アプリを一度閉じて開き直してもらいます。

### 更新が反映されないとき

| 確認すること | 内容 |
|---|---|
| キャッシュ | アプリを閉じて開き直す。それでも古いときは、ブラウザのサイトデータを消去する。ただし、データも消えるので、事前にバックアップを書き出す |
| サービスワーカーのバージョン | `sw.js` の `CACHE_NAME` を変更すると、古いキャッシュが入れ替わる |
| 公開の反映 | GitHubの **Actions** タブで、公開の処理が完了しているか確認する |

### バージョン表記

画面の見出し、`manifest.webmanifest`、`sw.js`、`Code.gs` の `VERSION` を、同じバージョンにそろえます。アプリの「GAS接続テスト」は、`Code.gs` の `VERSION` を見て、古いGASが動いていないかを判断します。

## 8. トークンを変更するとき

トークンが漏れた可能性があるときや、定期的に変えたいときの手順です。

1. 新しいトークンを決める。
2. `Code.gs`（Apps Script側）の `TRANSFER_TOKEN` を、新しい値に書き換える。
3. 新しいバージョンとしてデプロイする。
4. **すべての端末**で、アプリの設定の「転送トークン」を新しい値に入れ直す。
5. 「GAS接続テスト」と、実際の送信で確認する。

手順3と4の間は、送信が「転送トークンが一致しません」で失敗します。切り替えの時間帯を、利用者に伝えておいてください。

## 9. 停止・撤去するとき

| 作業 | 方法 |
|---|---|
| アプリの公開をやめる | GitHubの **Settings → Pages** で公開を停止する。またはリポジトリを非公開・削除する |
| メール送信を止める | Apps Scriptの **デプロイを管理** で、ウェブアプリのデプロイを削除（アーカイブ）する |
| 端末のデータを消す | 各端末で、設定の「全データ削除」を実行する |
